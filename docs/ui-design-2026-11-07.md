## Brief (from the owner, 7 Nov)

A professional, credible procurement-approval tool, English first. On every page a person must be able to answer:
which version am I looking at · where are the differences · who acts · what is next · is it approved or paid.
No full-site rewrite, no new dependency, no decorative animation, nothing hidden that is a blocker or a risk, no
pre-ticked confirmation, no state faked for the recording.

## Visual system ("conditions sheet")

Kept: the existing palette and system fonts (no web font — the app runs offline and adds no dependency).

- **Colour** (light / dark): ink `#1b1f24` / `#e8ebef`; surface `#ffffff` / `#171b21`; page `#f7f8fa` / `#0f1216`;
  rule `#dde1e6` / `#2a3039`; action blue `#0b5fff` / `#6ea0ff`; states — ok `#1f8f4e` / `#56d364`, needs action
  `#b88a00` / `#ffd84d`, blocked `#c23b32` / `#ff7b72`. MOCK flag stays the yellow chip. Colour is never the only
  signal: every state also has a word and a mark (✓ ! ✕ ○).
- **Type:** Segoe UI / system UI, Microsoft YaHei for Chinese. Scale 13 · 14 · 16 · 18 · 22 · 28 px. Page title 28 px
  (22 px narrow) names the **page**, not the record; the record title is a 16 px line under it. Money in tabular
  figures; the payment amount is the one large figure (28 px).
- **Space:** 4 · 8 · 12 · 16 · 24 · 32. Sections are cards (radius 10); cells inside them radius 6 — radius shows the
  level, not decoration.
- **Buttons:** one filled primary per decision region (Approve, Save classification, Start payment); outline secondary
  (Reclassify, Cancel); navigation stays a link. Disabled = 55 % + not-allowed cursor + the reason in text nearby.
- **Forms:** labels above fields; radios / checkboxes at natural size beside their text; no default choice where the
  choice is the decision.
- **Feedback:** saving… / saved (role=status) / refused with the server's reason (role=alert); nothing assumed from a
  POST — state is read back.
- **Focus:** a visible 2 px outline for every focusable element (global).

The one bold element: the **conditions sheet** at the top of the approval page — version, the amount, and the same three
status cells as the Quotes page. Everything else stays quiet.

## Approval page — new order (content unchanged, nothing removed)

1. Title "Approval of quote conditions 交易条件审批", record title under it, a line "You: … (buyer / approver) — what
   you can do here".
2. **Conditions sheet:** quote version (n of m, latest or not), request revision, extraction run (MOCK/LIVE); the amount
   and its basis; status cells Rule check / Approval / Payment; payments environment chip (MOCK / Sandbox / off).
3. **Decision:** blocking items (if any) → "Confirm before approving" (unticked checkboxes, approver only; read-only for
   the buyer) → Approve — or the Active approval notice.
4. **Approvals and payment** of this request (history, payment panel of the Active approval) — moved up so "Go to
   payment" lands next to the decision.
5. Money · Goods and terms · Free-text requirements (classification with history and **Reclassify**) · For your
   information · **Technical basis** (text hash, rules, payee, preview digest — moved down, still always visible).

## Reclassification (UX + minimal backend fix)

- Each classified requirement shows its current decision, reason, excerpt and time; earlier rows are listed under
  "Earlier classifications (n)" — the history is never rewritten.
- **Reclassify** (buyer only) opens the same form with **no decision pre-selected**; **Cancel** writes nothing.
- The form names the classification it replaces (`replaces`); the server refuses a stale or blind re-classification
  (409, fix `a7bfd6b`) and records an identical re-save as UNCHANGED (no row, no invalidation).
- If an Active approval exists, the form says before saving that it will make that approval no longer valid; after a
  payment it says the payment stays as it is and no new approval is possible.
- The first classification form also starts with no decision selected (the 6 Nov mis-selection started from a
  pre-selected "Not a key condition").
